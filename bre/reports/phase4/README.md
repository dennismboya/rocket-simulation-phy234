# reports/phase4/ — Phase 4 pre-registered evaluation on real data

This folder holds the outputs of `python -m bre.phase4` (PLAN.md section 6, applied verbatim by
`bre.eval.decision_rule`). Every number in the files below is generated by code from the data in
`data/processed/` (catalog entries B and C); nothing is typed by hand. This README describes the
outputs, the commands and the runtime budget; it carries no result numbers.

## Layout

One sub-folder per run, named after the dataset (`<dataset>[-n<subjects>][-smoke]`, or the
`name:` of the experiment YAML):

| file | content |
|---|---|
| `metrics.json` | everything: data summary, per-split tables (every model side by side: held-out NLL per response with the subject-bootstrap CI, Brier, ECE with the reliability table, AUC, WAIC/PSIS-LOO for B2, posterior-predictive NLL, parameter counts (all scalars and population-only), paired NLL difference vs the best classical model with its CI, per-subject predictive-gain distribution, fit diagnostics and timing), structural tests, the verdict, the fit settings and the command |
| `table.md` | the per-split model tables (parameter counts included) and the best classical / best Q-model of each split |
| `structural.md` | order effects by scenario from the data (pairs variant), the not-applicable notes for the LTP violation and the QQ equality, and per Q-model: the interference intervals (`delta_LTP` and `Delta_order` over the parameter draws), the decoherence-rate distribution (Q4) and the quarter-law check (Q5) |
| `verdict.json` | `{verdict, best_quantum, best_classical, nll_diff, ci95, interference_ci, n_params_q, n_params_c, data, ...}` — `verdict` is one of the two exact sentences of PLAN.md section 6 |
| `verdict.md` | the verdict with the conditions that held or failed, the data that would resolve it, and the decision rule verbatim |

The real tables are assembled by `bre.realdata` (Phase 4 mapping, deterministic subject
subsample) and cached as validated parquet under `runs/realdata/<dataset>-n<subjects>-seed<seed>.parquet`
(gitignored; real rows only, never under `data/synthetic/`), so a run or a worker reads its
subsample in about a second instead of rebuilding the 510,750-row CPC18 table. Delete that folder to
rebuild from `data/processed/`.

Fits, logs, per-job caches and model artifacts go to `runs/phase4/<name>/` (gitignored):
`phase4.log`, `jobs/<split>__<model>.pkl` (reused by later invocations with the same settings) and
`artifacts/<split>/<model>/` (a `bre.artifact.ModelArtifact` per fit; the split (b) winner is what
the dashboard would serve).

A folder whose name ends in `-smoke` is a timing / end-to-end check (60 subjects, one restart, 300
steps); its numbers are not results and must not be quoted as such.

## What is evaluated

* Data: CPC18 individual choices, pairs variant (`bre.realdata`): feedback blocks 2–5; subject =
  SubjID; scenario = problem; response = 1 if the lower-variance option was chosen (the retreat-to-
  safety analog of PLAN.md section 6 — an analog, not panic selling); context = `exp:loss` /
  `exp:gain` of the two preceding trials in chronological order; `loss_pct` = previous obtained
  payoff / largest absolute outcome of the problem (signed), null where the previous payoff was not
  displayed. Secondary: Psych-201 `spektor2024lossaversion` (context = outcome domain; no ordered
  pairs, so split (b) and the positive verdict are not reachable there).
* Splits: (a) held-out subjects 20%; (b) train on the rows with at most one `exp:*` tag, test on
  the ordered pairs; (c) not applicable — no real table in hand has a question-order manipulation
  (recorded in the outputs with that reason); (d) temporal, the last 20% of every subject's trials.
* Models: every registered model (B1, B2 via SVI, B3, B4, B5 via its external fit, B6, Q2, Q3 at
  its default time, Q4, Q5) with the same fit driver and settings.
* Decision rule: best Q-model vs best classical on split (b) by held-out NLL with a paired subject
  bootstrap, matched-or-lower parameter count, interference-term CI excluding zero. On tables without
  a tolerance question the `delta_LTP` interval is a model-internal counterfactual (`phi` is not
  identified); `structural.md` and `verdict.md` say so next to the number.

## Commands

Smoke (timing and end-to-end check; equivalent to `--config experiments/p4-cpc18-smoke.yaml`):

    /home/user/bre-venv/bin/python -m bre.phase4 --dataset cpc18 --smoke

Wall-time estimate of a run without fitting anything (scales the measured smoke costs by rows):

    /home/user/bre-venv/bin/python -m bre.phase4 --config experiments/p4-cpc18-full.yaml --estimate-only

Full CPC18 run (all 686 subjects, PLAN.md section 4 settings; see the budget below before starting):

    /home/user/bre-venv/bin/python -m bre.phase4 --config experiments/p4-cpc18-full.yaml

Secondary dataset:

    /home/user/bre-venv/bin/python -m bre.phase4 --config experiments/p4-psych201-spektor2024.yaml

Splitting a long run: every `(split, model)` job is cached under `runs/phase4/<name>/jobs/`, so the
same command can be issued with `--models` subsets in separate background invocations (or with
`--splits`), and a final call with the full model list assembles the tables and the verdict from the
caches without refitting. `--refit` ignores the caches; `--workers N` runs N single-threaded jobs in
parallel (as `bre.recover`).

## Runtime budget (measured on the smoke run, scaled by rows)

RUNTIME_SECTION_PLACEHOLDER

A run over two hours wall-clock is a GATE (CLAUDE.md rule 4): the main session must split it
(`--models` subsets in separate invocations, fewer restarts or steps, or `--subjects N`) or ask the
owner, and must record in STATUS.md what was actually run. `--estimate-only` prints the per-job and
total estimate from the same table before anything is fitted.
